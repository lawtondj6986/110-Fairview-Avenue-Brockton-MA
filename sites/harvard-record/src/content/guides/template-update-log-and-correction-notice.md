Published research needs two things for handling change: a notice on the affected page, and an entry
in a central log that lists every change in one place. This page gives fill-in wording for both. The
reasoning is in the guide on correcting your own work in the Research methods series under
`/guides/`. This site's own process is described at `/methodology/`.

Use the right label. A correction fixes something that was wrong. A clarification fixes something
accurate that could be misread. An update records that the facts have moved on since publication. A
withdrawal removes a claim whose basis has failed.

## Notices for the affected page

```text
CORRECTION (simple fact)
Correction, [date]: An earlier version of this page stated that
[what was wrong, in neutral terms]. [Correct statement.] The text has
been corrected. [Source: (citation).]

CORRECTION (figure)
Correction, [date]: An earlier version of this page gave the
[description of figure] as [old figure]. The [source] states
[correct figure]. The text and the [table / chart] have been corrected.

CORRECTION (about a person, where repeating the error would cause harm)
Correction, [date]: An earlier version of this page misstated
[name]'s [role / connection to the matter / the date of an event].
The text has been corrected. We apologize to [name] for the error.

CORRECTION (evidence state or grade)
Correction, [date]: An earlier version of this page described
[event] as having taken place. The cited source shows that it was
proposed, and we have found no record that it occurred. The text now
says so.

CLARIFICATION
Clarification, [date]: This page has been revised to make clear that
[what the text is and is not saying]. The earlier wording could have
been read to suggest [unintended meaning], which the sources do not
support.

UPDATE (new information)
Update, [date]: Since this page was published, [what has happened: a
document was released / a court ruled / a report was issued]. The page
now reflects [the change]. Source: [citation].

UPDATE (response received)
Update, [date]: [Name or institution] provided a response after
publication. It has been added [in the section titled "..."].

UPDATE (source verified)
Update, [date]: The statements on this page that cite [source] were
previously marked as pending check. The original document was opened
and the cited passages confirmed on [date]. [No changes were needed. /
The following changes were made: ...]

WITHDRAWAL OF A CLAIM
Withdrawn, [date]: This page previously stated that [claim, in
neutral terms, or "a claim about (subject)" where repeating it would
cause harm]. The source for that statement [has been corrected by its
publisher / could not be verified / does not support the statement].
The statement has been removed.

WITHDRAWAL OF A PAGE
This page was withdrawn on [date] because [reason]. [A corrected
account is at (path). / The matter is recorded in the update log.]
```

## Update-log entry

```text
UPDATE LOG ENTRY

Date:            [YYYY-MM-DD]
Type:            [correction / clarification / update / withdrawal /
                  new page / source verified]
Page(s):         [path of each affected page]
Summary:         [one or two plain sentences: what changed]
Before:          [the earlier wording, or a neutral description of it]
After:           [the current wording]
Reason:          [what prompted the change: new document, reader
                  report, subject's reply, own recheck]
Source:          [Source ID and pinpoint supporting the current text]
Claims affected: [Claim IDs from the claim ledger]
Also changed:    [tables, charts, summaries, downloads, other pages]
Page review date
changed to:      [YYYY-MM-DD]
Entered by:      [initials]
```

A compact form for a public log page:

```text
[YYYY-MM-DD] [Type]: [Page title] ([path]). [What changed, in one
sentence.] [Source, if new.]
```

## Notes on wording

Say what was wrong and what is right. A reader should not need to compare versions to understand the
change. "This page has been updated" tells them nothing.

Use the plain word. If the text was wrong, call it a correction. Reserve "update" for cases where
the original was accurate when published.

Keep it short and neutral. A notice states the change. It does not argue, justify or describe how
the error arose. That analysis belongs in your private notes.

Do not amplify harm. Where the error was a damaging statement about a person, describe the
correction without restating the false claim more prominently than it first appeared. The third
notice above shows one way. Balance this against clarity: a reader must still be able to tell what
was changed.

Apologize where harm was done. One direct sentence is enough. Do not apologize in a way that
restates the claim.

Do not blame. Leave out references to who reported the error or who made it, unless the person who
reported it asks to be credited.

Date everything. Use the date the change was published. If a page is corrected more than once, keep
each notice, newest first.

Mark new information as new. When a later document changes the picture, an update notice with its
source is the honest form. Do not quietly rewrite the page as though it had always said so.

## Placement

- Put the notice on the affected page, either beside the corrected passage or in a clearly labeled
  section at the foot of the page.
- Change the page's "last reviewed" or "last updated" date.
- Add the log entry on the same day. Link the log entry to the page and, if practical, the notice to
  the log.
- If the same claim appeared on several pages, place a notice on each one and list all of them in a
  single log entry.
- If the erroneous claim was sent out by another route, such as a newsletter or a post, send the
  correction by the same route.
- Leave notices in place permanently. Do not remove a correction notice after a period of time.

## What does not need a notice

Fixing a typo, repairing a broken link or adjusting layout does not change meaning and usually needs
no notice. Decide this rule in advance and write it down. If an edit changes a name, a number, a
date, a quotation, an attribution, an evidence state or a grade, it is substantive and gets a
notice, however small it looks.

## Adapting the template

A small project can keep the log as a single dated list using the compact form. A larger one should
keep the full entry privately and publish the compact form. In either case, the public log should
let a reader see every substantive change the work has undergone, in date order, without asking.

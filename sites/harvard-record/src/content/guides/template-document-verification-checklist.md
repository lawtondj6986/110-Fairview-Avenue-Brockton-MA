Use this checklist once for each document you intend to rely on. It records what you did to
establish that the document is what it appears to be, and what the document can and cannot support.
The reasoning behind each step is in the guide on verifying a document's authenticity in the
Research methods series under `/guides/`.

A completed checklist does not prove a document genuine. It shows what was checked, when, by whom
and with what result, so that a later reader can judge the decision.

## The template

```text
DOCUMENT VERIFICATION CHECKLIST

Source ID:               [from the source log]
Document title:          [exact title]
Stated author or issuer: [as shown on the document]
Stated date:             [as shown on the document]
Checked by / date:       [initials] / [YYYY-MM-DD]

A. PROVENANCE
[ ] Where I first encountered the document: [site, article, release]
[ ] Official origin identified: [court docket / agency site /
    institution's own site / records release / none found]
[ ] Copy obtained directly from the official origin
    Address or identifier: [URL, docket entry, request number]
    Date obtained: [YYYY-MM-DD]
[ ] If first seen elsewhere: official copy compared with that copy
    Result: [identical / differences found: describe]
[ ] If no official copy: established reporting describes the
    document and quotes the passages I need
    Reporting source ID: [ID]
[ ] Archived capture made of the page or file: [archive URL, date]
[ ] Local copy saved: [file name]

B. FORM
[ ] Format matches other documents from the same issuer and period
[ ] Identifying marks present and consistent on every page
    (case number, filing stamp, page identifiers, letterhead,
    reference number): [note]
[ ] Page count complete; numbering continuous: [pages x of y]
[ ] Attachments and exhibits listed are present: [yes / missing: list]
[ ] Signature or execution: [signed and dated / unsigned / draft /
    not applicable]
[ ] Version identified: [final / draft / amended / superseded by (ID)]
[ ] Redactions noted: [none / present on pages (list); exemption or
    reason stated: (note)]

C. INTERNAL CONSISTENCY
[ ] Dates within the document fall in a possible order
[ ] Names, titles and organization names fit the stated date
[ ] Terminology, addresses and formats fit the stated date
[ ] No unexplained changes of font, layout or alignment
[ ] File metadata reviewed: [fields read and what they show; or
    "not reviewed"]
    Caution noted: metadata dates may reflect scanning or conversion.

D. CORROBORATION
[ ] An independent record confirms at least one specific detail
    Detail and source: [note, Source ID]
[ ] Neighboring documents are consistent (replies, forwards, cover
    letters, docket entries before and after): [note]
[ ] An official body or established outlet has quoted this document
    and the quotation matches my copy: [Source ID, pinpoint]
[ ] Anything that contradicts the document: [none found / describe]

E. WHAT THE DOCUMENT IS
[ ] Kind of record: [finding or decision / official report /
    allegation or pleading / correspondence / proposal or draft /
    financial record / statement or press release / other]
[ ] Who is speaking: [the issuer / a party / a third party quoted
    within it]
[ ] Highest evidence state it can support: [stated intent /
    documented activity / verified implementation]
[ ] Grade assigned: [A1 / A2 / B1 / B2] because [one line]
[ ] Scope limits stated by the document itself: [note]

F. CARE
[ ] Contains personal information about private individuals:
    [no / yes: will not be reproduced]
[ ] Contains or appears to contain sealed or wrongly released
    material: [no / yes: do not use; do not circulate]
[ ] Names people only as recipients or bystanders: [no / yes: note
    for the text]

G. DECISION
[ ] Authenticated: obtained from or matched to the official origin.
[ ] Probably authentic, not traced: cite the reporting, not the
    document, and say so.
[ ] Unverified: do not rely on it; keep as a lead only.

Open questions:  [anything unresolved]
Recheck by:      [date, if a pending release or request may settle it]
```

## Notes on using it

Do section A first. Provenance is the strongest test. If you can obtain the document from its
official origin, many of the later checks become confirmation instead of detective work. If you
cannot, no amount of internal checking fully makes up for it.

Unticked boxes are information. Leave a box empty when a check was not done or could not be done,
and say why in the open questions field. A checklist with every box ticked by habit is worth less
than one with honest gaps.

Section C is a screen, not a proof. Internal consistency catches careless forgeries and mislabeled
documents. A consistent document may still be inauthentic, and an authentic one may contain oddities
with ordinary explanations, such as a letter printed later on newer letterhead.

Treat metadata carefully. Record exactly which fields you read. Creation and modification dates
often reflect when a paper original was scanned or a file was converted. Author fields often name
whoever owns the software. Draw no conclusion from metadata alone.

Section E separates authenticity from meaning. A genuine complaint is still a set of allegations. A
genuine draft is still a draft. Deciding what kind of record you hold, and the highest evidence
state it can support, prevents an authentic document from being used for more than it shows. The
states and grades are defined at `/methodology/`.

Section F is not optional. If a document contains private information, sealed material or text that
appears to have been released by mistake, the question is no longer only whether it is authentic.
See the ethics guide in the Research methods series.

The three decisions lead to different citations. An authenticated document is cited directly, with
its formal identifier. A document you could not trace is not cited as a document: cite the
established reporting that describes it, at the grade of that reporting. An unverified document is
not cited at all.

## Adapting the template

- Court filings: add the court, the case number and the docket entry number, and check the filing's
  later history (amended, struck, sealed, or ruled on).
- Emails: add fields for sender, recipients, copied recipients, time zone and position in the
  thread, and check whether a fuller version of the thread exists.
- Financial and tax filings: add the entity's legal name and identifying number, the period covered
  and whether an amended filing exists.
- Web pages: add the capture date and note whether the page has changed since.
- Batches: for a large release, complete section A once for the release as a whole, then sections B
  to G for each document you rely on.

## Filing

Store the completed checklist with the document's source log entry, and copy the decision and date
into that entry's authenticity field. When new information arrives, complete a fresh dated checklist
and keep the old one.
